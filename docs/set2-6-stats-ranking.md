# SET2-6 戦績・ランキング：保存範囲と公開条件

> ステータス: **設計確定**
> 対応チケット: [SET2-6](https://linear.app/setsuna-no-puyuri/issue/SET2-6)
> 前提: [SET2-7](./set2-7-embed.md)（kusa は識別情報を渡さない）、[SET2-4](./set2-4-sync-fairness.md)、[SET2-2](./set2-2-realtime-match.md)

## 1. 前提と方針

kusa からユーザー識別情報は一切渡されない（SET2-7 §2）。
継続的なランキングは「同じ人」を追跡できないため原理的に成立しない。

**そこで、そもそも継続させない。**

- ランキングは**その日だけ**。JST の 00:00 で全部リセットする
- 識別子は**こちらで発行する非公開の Cookie**。kusa とは無関係
- kusa は「人が来る場所」と割り切る。認証基盤とは考えない

この方式は同じ作者の先行実装 [`kusa-machi`](https://github.com/) で実戦を通っている。
本書はその設計を踏襲する。

### 1.1 日次リセットは不正対策としても効く

SET2-4 §8 の限界4「匿名環境では不正者を継続的に排除できない」は、
**継続させなければ限界にならない**。

Cookie を消せば別人になれるし、複数ブラウザで多重参加もできる。
だが翌日には全部消えるので、**積み上がらない**。労力に見合わない。

同時に、SET2-6 の要件「保持期間、削除方法を定義する」も自動的に満たされる。

---

## 2. ゲーム日

**JST の暦日**をゲーム日とする。`2026-09-13` のような日付文字列がキーになる。

- 00:00 JST に切り替わる
- 日付に関わる処理は `Date.now()` を直接使わず、時計を1か所に集約してテストできるようにする
- **日次リセットはクエリをゲーム日でスコープすることで成立させる。**
  古い行は「見えない」から消えているのであって、削除されたからではない
- 物理削除は容量回収だけが目的。**遅れても、二重に動いても、動かなくても安全**

## 3. 匿名識別子

### 3.1 Cookie

| 項目 | 値 |
|---|---|
| 名前 | `puyuri_token` |
| 中身 | UUID **のみ**。ゲームの状態は一切持たせない |
| 属性 | `HttpOnly` / `Secure` / `SameSite=None` / **`Partitioned`** / `Path=/` |
| 有効期限 | 約30日。**毎リクエストで書き直してスライドさせる** |

### 3.2 `Partitioned` が要（重要）

**`SameSite=None` だけでは足りない。**

iOS Safari などサードパーティ Cookie を遮断するブラウザでは、
`SameSite=None` を付けても iframe 内の Cookie は保存されない。
その結果、リクエストのたびに別人が作られて戦績がまったく積み上がらない。

`Partitioned`（CHIPS）を付けると、**埋め込み元サイトごとに分離された領域**に保存され、
遮断下でも機能する。属性を知らない古いブラウザは無視するだけなので、付けて損はない。

> これは kusa-machi が実際に踏んだ問題で、そこで得た解決策。
> 自力で設計すると `SameSite=None; Secure` で終わりにしてしまい、iOS Safari で壊れる。

### 3.3 保存されなかった場合を検出する

Cookie を伴わないリクエストが2回目以降も続くなら、そのブラウザは Cookie を保存していない。
サーバーは「Cookie を受け取ったか」を毎回返し、クライアントはそれが続いたら表示する。

> この環境では記録が残りません

**対戦自体はできる。** ランキングに載らないだけ。

### 3.4 非公開であること

`puyuri_token` は **HttpOnly なので JS からも読めない**。
API のレスポンスにも、ランキングにも、相手にも、一切出さない。

外に出るのはサーバーが発行した**その日限りの表示名**だけ（§4）。

## 4. その日限りの二つ名

ランキングに「ぷゆ」ばかり並んでも区別がつかない。かといって名前を入力させると
kusa の「匿名で遊べる」から外れるし、入力の手間で離脱する。

**サーバーが、その日限りのランダムな二つ名を自動で振る。**

```
夜半のぷゆ / 三日月のぷゆ / 霜降りのぷゆ / 一閃のぷゆ …
```

- 入力を求めない
- 匿名のまま区別がつく
- **翌日には別の名前になる**ので、名前で人を追跡できない
- `(token, ゲーム日)` に対して1つ決まる。同じ日は同じ名前

kusa-machi の「その日限りのランダム生成ペルソナ」と同じ発想。

## 5. 保存するもの

### 5.1 試合結果

| 項目 | 用途 |
|---|---|
| `resultId` = `matchId:roundId` | **一意キー。** 同じキーの2回目の書き込みは捨てる（SET2-2 §6.2） |
| ゲーム日 | スコープ |
| 参加者2人の `token` | 戦績の紐付け。**公開しない** |
| 各自の判定結果・反応時間 | 記録 |
| `recorded` | false なら集計に入れない |

**クライアントから勝敗を直接書き込ませない。** 書き込むのは判定したサーバーだけ。

### 5.2 日次戦績

`(token, ゲーム日)` ごとに1行。

| 項目 | 内容 |
|---|---|
| 試合数 / 勝ち / 負け / 引き分け | カウント |
| **最速反応時間** | その日の自己ベスト（ms） |
| **現在の連勝数** | いま何連勝中か |
| **その日の最長連勝** | ランキング用 |
| 各記録の達成時刻 | 同点順の判定に使う |

## 6. ランキング

**2本立て**にする。片方は個人技、もう片方は勝負強さで、性格が違う。

### 6.1 最速反応時間

その日の `最速反応時間` の**昇順**。

対象にするのは次を**すべて**満たすラウンドのみ。

- `recorded === true`
- フライングでない / 速すぎない（`R >= R_min`）/ 無入力でない / 切断でない

**負けた試合の反応時間も対象にする。** 速さの記録であって勝敗の記録ではない。
相手がもっと速かっただけで、自分の反応が遅かったわけではない。
負けても自己ベストが出ることがあるのは、体験として救いになる。

### 6.2 連勝記録

その日の `最長連勝` の**降順**。元ネタの勝ち抜き構造がそのまま指標になる。

連勝の増減:

| 結果 | 連勝 |
|---|---|
| 勝ち（切断による不戦勝を含む） | **+1** |
| 負け | **0 にリセット** |
| 引き分け・相打ち | **維持**（増えないが切れない） |
| 無効試合・記録されない試合 | **維持**（ノーカウント） |

引き分けで切らないのは、同着幅 `D = 20ms` があるため引き分けが一定の頻度で出るから。
そこで切ると連勝が伸びず、指標として機能しない。

### 6.3 同点順

**先に記録した方が上。** 後から同じ記録を出しても抜けない。

説明しやすく、先行者が守られる。連打で並ぶ意味がなくなるので荒れにくい。

### 6.4 公開するもの

| 出す | 出さない |
|---|---|
| 順位 | `puyuri_token` |
| その日限りの二つ名 | kusa の識別子（そもそも受け取らない） |
| 記録（ms / 連勝数） | IP アドレス・UA・端末情報 |
| 達成時刻（同点順の根拠として必要なら） | 対戦相手が誰だったか |

## 7. MVP の内外

| MVP に入れる | 入れない |
|---|---|
| 本人向けの当日戦績（勝敗数・自己ベスト・現在の連勝） | 通算成績・レーティング |
| 当日ランキング2種（最速・連勝） | 週間/月間ランキング |
| その日限りの二つ名 | 名前の入力・変更 |
| 記録されない試合の除外 | 手動の訂正・取り消し |
| | 対戦履歴の閲覧・リプレイ |

## 8. 残る限界（SET2-8 へ引き渡し）

1. **Cookie を消せば別人になれる。** 防げない。1日でリセットされるので実害を抑える
2. **複数ブラウザ・複数端末で多重参加できる。** 同上
3. **Cookie を保存しないブラウザでは記録が残らない。** 検出して表示はするが、防げない
4. **申告値の改ざんは防げない**（SET2-4 §5.3 で整合性検査を廃止）。
   **101ms を申告するボットが最速ランキングの1位になりうる。**
   防げるのは `R < 100ms` だけ。日次リセットと賞品が無いことで割に合わなくするのが現実的な落としどころ
5. **談合できる。** 2人で示し合わせて片方を勝たせ続ければ連勝を伸ばせる。
   1日で消えること、順位以外に得るものが無いことで割に合わなくしている
6. **端末のリフレッシュレート差が最速記録に効く**（SET2-4 §8 限界2）。
   120Hz 端末が有利。**ランキングに端末差の影響が残ることを明示する**

### 8.1 公開時に一行添えるもの

> 記録は毎日 0 時にリセットされます。端末や回線によって記録は変わります。
